# SIM CORE: A DETERMINISTIC TICK KERNEL (2026-10-02)

**GATE:** none · **Priority:** P1 · **Size:** M · **Depends on:** asset-kit-core (`packages/det`)

## Origin
D2 (our own engine), D10 (games are pure data, the player is swappable, Godot may come later)
and D23 (the queue covers the whole engine). The simulation is the part of the engine a second
player must reproduce exactly, so it is built deterministic and headless from the first line.

## Scope
1. `packages/sim` (TypeScript; depends only on `det`; no DOM, WebGL, `Date`, timers, `fetch` or
   storage; under the determinism lint):
   - **kernel:** fixed integer ticks, no `dt`; `createSim({ data, seed })`, `step(n)`;
   - **commands in:** `{ tick, type, payload }`, serialised canonically; the only way to change
     state from outside; ordered by tick, then by sequence number;
   - **events out:** a per-tick event list the host reads (for FX, audio cues and UI);
   - **state:** plain data in declared tables; entities with stable integer ids; ordered
     collections are arrays; maps are iterated by sorted key; every comparator is a total order;
   - **systems:** engine modules registered in a fixed order. A game lists the systems it uses
     and supplies their data tables; a game contains no code (D10);
   - **PRNG:** one named stream per system, from `det`;
   - **digest:** a canonical binary encoding of the state (fixed field order, little-endian
     integers, entities sorted by id) hashed with FNV-1a 32; never a hash of formatted text;
   - **snapshot / restore:** canonical and versioned;
   - **replay:** `{ simDataHash, seed, commands }` → digests, with a Node runner
     `./dev npm run sim -- replay <file>`;
   - **state as text:** `describe()` returns a compact text form of the state for agents.
2. A toy system set for the tests, `counter-shop`: customers arrive by RNG and buy, money grows,
   a command changes the price. It exercises commands, events, RNG streams and the digest.
3. `docs/sim.md`: the sim contract in ≤ 2 pages (ticks, commands, events, ordering rules, what
   is banned and why).

## Out of scope
- Genre systems (grid placement, pathing, visitors, staff, economy, calendar): they come with
  the first game's notes, gated by OC-A6.
- Rendering, input, audio and storage: host adapters (`player-loop-test-protocol`).
- Running the sim on other JS engines (`sim-conformance-quickjs`).

## Acceptance
- Golden replay: the same seed and commands give the stored digests; `npm run check` runs it.
- Snapshot → restore → continue gives the same digests as an uninterrupted run. **Heavy mode**
  (save and load on every tick) gives them too.
- Adding an unrelated RNG stream or system data row does not change another system's stream.
- A fuzz test (1,000 random command sequences) never throws and never produces a non-integer
  in the state.
- The determinism lint covers `packages/sim`; a fixture using `Math.random()` fails.
