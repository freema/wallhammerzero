## 1. GPU particle architecture on SDL_GPU compute without bindless (emit / simulate / compact / sort / render; atlases; indirect draws; depth collision; sorting vs OIT; soft particles; cheap stylised lighting; half-res; LOD/culling; pooling; determinism)

### Takeaway
The proven pattern (Gareth Thomas/AMD 2014 → Wicked Engine, still in Wicked's master today) is: fixed-size particle pool + dead-list stack + ping-pong alive lists + a GPU counter buffer, with tiny 1-thread "kickoff"/"finish" compute passes that write indirect dispatch and draw arguments, so the CPU never reads back counts. Every piece maps onto SDL_GPU (storage buffers, `DispatchGPUComputeIndirect`, `DrawGPUPrimitivesIndirect` with `draw_count = 1`), and none needs bindless if textures live in one texture array and emitter parameters live in a storage buffer. Sorting, half-resolution rendering and depth collisions are optional per-emitter flags, not core requirements; stylised VFX mostly avoid global sorting by using premultiplied alpha, few layers, and short lifetimes.

### Cited Findings

**Wicked Engine GPU particles (read from source, master branch, fetched 2026-11-05)**
- Particle struct is 64 bytes: `float3 position; float mass; float3 force; uint rotation_rotationVelocity (packed half2); float3 velocity; float maxLife; float2 sizeBeginEnd; float life; uint color` — [ShaderInterop_EmittedParticle.h](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/ShaderInterop_EmittedParticle.h)
- Counter buffer: `aliveCount, deadCount, realEmitCount, aliveCount_afterSimulation, culledCount, cellAllocator`; indirect-args struct holds one dispatch and two instanced draws (`draw_culled`, `draw_all`) — [ShaderInterop_EmittedParticle.h](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/ShaderInterop_EmittedParticle.h)
- Simulation: thread `i < aliveCount` reads `aliveBuffer_CURRENT[i]`; surviving particles `InterlockedAdd(aliveCount_afterSimulation)` and append into `aliveBuffer_NEW`; dead ones `InterlockedAdd(deadCount)` and push their index back into `deadBuffer`; visible ones (sphere vs camera frustum) are appended to `culledIndirectionBuffer` and, when sorting is on, write `-asuint(distSQ)` into a distance key buffer ("negated to modify sorting order … instead of rewriting sorting shaders") — [emittedparticle_simulateCS.hlsl](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/emittedparticle_simulateCS.hlsl)
- Kickoff pass is `[numthreads(1,1,1)]`: computes `ThreadGroupCountX = (aliveCount + THREADCOUNT_SIMULATION − 1) / THREADCOUNT_SIMULATION`, swaps `aliveCount_afterSimulation → aliveCount`, clamps `deadCount ≥ 0`, zeroes `culledCount` — [emittedparticle_kickoffUpdateCS.hlsl](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/emittedparticle_kickoffUpdateCS.hlsl)
- Finish pass (1 thread) writes `IndirectDrawArgsInstanced{VertexCountPerInstance = 4, InstanceCount = culledCount}` (quad from vertex ID) and a second one with `aliveCount` for shadow/other passes — [emittedparticle_finishUpdateCS.hlsl](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/emittedparticle_finishUpdateCS.hlsl)
- Simulation thread group is 256 (64 when the SPH hashed grid is enabled); emit dispatch is `(count + 63) / 64` groups; emit RNG is seeded with `(xEmitterRandomness, DTid.x)` and `frame_count` — [ShaderInterop_EmittedParticle.h](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/ShaderInterop_EmittedParticle.h), [emittedparticle_emitCS.hlsl](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/emittedparticle_emitCS.hlsl), [wiEmittedParticle.cpp](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/wiEmittedParticle.cpp)
- Sorting is a separate GPU sort library call on the culled list keyed by distance (`wi::gpusortlib::Sort(MAX_PARTICLES, distanceBuffer, counterBuffer, offsetof(culledCount), culledIndirectionBuffer)`), only for emitters with the "sorted" flag; shader permutations exist for {plain, SORTING, DEPTHCOLLISIONS, both} — [wiEmittedParticle.cpp](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/wiEmittedParticle.cpp)
- Depth-buffer collision uses the **previous frame's** depth and previous view-projection: project the particle, read depth, treat a hit if within `particleSize` and a fixed `surfaceThickness = 1.5`, reconstruct 3 world positions from neighbouring depth texels, normal = `normalize(cross(p2 − p0, p1 − p0))`, reflect velocity × restitution if moving into the surface — [emittedparticle_simulateCS.hlsl](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/emittedparticle_simulateCS.hlsl)
- Emitter option bits include frame blending (flipbook crossfade), SPH, mesh shader, colliders disabled, **use rain blocker**, take colour from mesh; CB has flipbook `framesXY / frameCount / frameStart / frameRate`, drag, gravity, restitution, and a `xEmitterFixedTimestep` ("force a fixed timestep (>0) onto the simulation to avoid blowing up") — [ShaderInterop_EmittedParticle.h](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/ShaderInterop_EmittedParticle.h)
- Pixel shader variants in Wicked: `simple`, `soft`, `soft_distortion`, `soft_lighting`, `shadow` — [Wicked repo tree](https://github.com/turanszkij/WickedEngine/tree/master/WickedEngine/shaders)
- Wicked's 2017 blog post describes the design as two alive index lists ("the emitter writes the first one, simulation kills dead particles and writes the alive list again to draw later"), indirect argument buffers, and credits Gareth Thomas's compute particles as inspiration (seen via search snippet; page itself returned 404 on fetch) — [Wicked Engine blog, 2017-11](https://wickedengine.net/2017/11/gpu-based-particle-simulation)

**Destiny (Bungie, SIGGRAPH 2017 Advances, Brandon Whitley)** — only a third-party summary was readable
- Particle systems are node graphs whose per-node parameters (size, colour…) are **expressions**; an expression-to-HLSL converter and a bytecode interpreter run on both CPU and GPU; adding GPU particles needed "relatively simple changes"; "motion primitives" (spheres, points, planes) steer particle motion; goals were "sub-second iteration" and high performance — [80.lv summary](https://80.lv/articles/siggraph-the-destiny-particle-architecture/)

**Unreal Niagara (concepts to borrow)**
- Hierarchy: System → Emitters; emitter stack groups Emitter Spawn (once, CPU), Emitter Update (per frame, CPU), Particle Spawn, Particle Update, Event Handler, Render; modules execute "sequentially from top to bottom", each reads data, does math, writes back; parameters are Primitive/Enum/Struct/Data Interface — [Niagara overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-niagara-effects-for-unreal-engine)
- Scalability: reusable **Effect Type** assets with per-quality/per-platform overrides that cull instances, scale particle counts, disable renderers/emitters; "System as a Service" merges bursts (e.g. projectiles) into one long-lived system; pooling of components; "a simulation of 1 particle can potentially take up the same resources as one with 64 particles"; fixed bounds are generally cheaper than dynamic bounds; avoid warm-up ("each frame in the warmup needs to be evaluated sequentially"); spread large bursts over several frames; sorting is off by default and costs GPU time + index memory — [Niagara scalability & best practices](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-and-best-practices-for-niagara)

**Low-resolution (off-screen) particles — GPU Gems 3 ch. 23 (Iain Cantlay)**
- Pipeline: opaque with depth → downsample depth → render particles into a smaller RT depth-tested against it → composite. Downsample with **max of 4 depth samples** (an "expedient hack" that shrinks silhouettes but removes halos). Alpha-blended particles need separate alpha blend (`Src=SrcAlpha, Dst=InvSrcAlpha, SrcA=Zero, DstA=InvSrcAlpha`, RT cleared to black) to store the destination occlusion; additive particles just accumulate. Optional mixed-resolution fix-up: Sobel edge detect on the low-res result → stencil → re-render particles at full res only on edges — [GPU Gems 3 ch. 23](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-23-high-speed-screen-particles)
- Numbers (GeForce 8800 GTX, 1600×1200): full res 25 fps / 46.9 M particle pixels; low-res 4×4 61 fps / 2.9 M; mixed 4×4 51 fps; 2×2 low-res 46 fps / 11.7 M. Suits soft low-frequency smoke/fog, not debris; "can never be entirely free of artifacts" — [GPU Gems 3 ch. 23](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-23-high-speed-screen-particles)
- Soft particles: `alpha *= saturate(scale * (sceneDepth − particleDepth))` — [GPU Gems 3 ch. 23](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-23-high-speed-screen-particles)

**Order-independent alternative — Weighted Blended OIT (McGuire & Bavoil, JCGT 2013; blog 2014)**
- Two targets: RT0 ≥ RGBA16F additive (premultiplied colour × weight), RT1 ≥ R8 with `(ZERO, ONE_MINUS_SRC_ALPHA)` "revealage"; full-screen composite divides colour by accumulated alpha. No sorting, less bandwidth than a k-buffer; weight function must be tuned per depth range and opacity (designed for ~1–100 surfaces, α ≈ 0.2–0.9); no refraction; explicitly suited to particles and to low-resolution smoke interleaved with high-res content — [Casual Effects blog](https://casual-effects.blogspot.com/2014/03/weighted-blended-order-independent.html)

**Lighting particles**
- DOOM (2016): particle lighting is computed per sprite as if in world space (light list + shadow maps at the sprite position), stored in tiles of a 4K atlas (tile size by distance/quality, e.g. 64×64), then the low-res lighting quad is upscaled and blended with the full-res particle texture, so cost is independent of output resolution; particle simulation is a compute shader that reads previous state plus **normal and depth buffers** for collisions — [Adrian Courrèges, DOOM (2016) graphics study](https://www.adriancourreges.com/blog/2016/09/09/doom-2016-graphics-study/)

**SDL_GPU indirect draw**
- `SDL_DrawGPUPrimitivesIndirect(render_pass, buffer, offset, draw_count)` (SDL 3.2.0+) reads tightly packed `SDL_GPUIndirectDrawCommand`s; a graphics pipeline must be bound — [SDL3 wiki](https://wiki.libsdl.org/SDL3/SDL_DrawGPUPrimitivesIndirect)
- Engine constraint already recorded: no bindless; Metal multi-draw indirect is a CPU loop; no timestamp queries — [DECISIONS.md D5](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/DECISIONS.md)
- threejs-punk mapping already found that GPU rain needs 2–4 RW storage buffers (SDL_GPU limit 8) + 1 sampled texture, VS reads a storage buffer via `SV_InstanceID` and builds the quad from `SV_VertexID`; "bindless ani indirect netřeba" — [threejs-punk.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

**Determinism (gameplay vs cosmetic)**
- Engines offer fixed-timestep particle updates for stability when particles do collisions (Flax), and GPU particles at a fixed rate with interpolation to display rate (Godot); Godot warns long lifetimes are expensive on GPU — [Flax docs](https://docs.flaxengine.com/manual/particles/particle-effect.html), [Godot GPUParticles2D](https://docs.godotengine.org/es/4.x/classes/class_gpuparticles2d.html)
- Some engines split deterministic CPU particle sims from optional GPU compute for rendering (Scenix 1.7.0 release notes, minor project) — [Scenix release](https://github.com/aarambhdevhub/scenix/releases/tag/v1.7.0)
- Voxel Musou ages VFX in **simulation frames** (sub-step 1/30), packs live particles from slot 0, and during hitstop ages VFX at half speed so sparks "hang" with the hit — [voxel-musou.md §4.5](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/voxel-musou.md)
- threejs-punk rain integrates `position += velocity` without `dt` (rain falls 2× faster at 120 Hz) and seeds respawn with `float(index) + time·1000` (float precision decays over hours); recommended fix is a uint PCG hash with a frame counter — [threejs-punk.md §1](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

### Inferences
- **One global particle pool, not one buffer set per emitter.** Wicked allocates buffers per emitter, which means N× (emit + kickoff + simulate + finish + draw) per emitter — fine for an editor, too many passes for a city with 200 live effects. Proposal: a single pool (e.g. 256k–1M slots × 48–64 B ≈ 12–64 MB) with a shared dead list; every particle stores a 16-bit `emitter_type` + 16-bit `instance` index; per-type parameters (curves, flipbook layer range, blend bucket, forces) sit in one `StructuredBuffer<EmitterType>` and per-instance state (transform, seed, spawn budget, user params) in another. Then the whole frame is: 1 emit dispatch (spawn requests list built on CPU), 1 kickoff, 1 simulate, 0–1 sort, 1 finish, and **one `DrawGPUPrimitivesIndirect(draw_count=1)` per render bucket**. Because each indirect call has `draw_count = 1`, the Metal "MDI is a CPU loop" limitation does not matter.
- **Render buckets instead of per-emitter draws:** (a) alpha-clip/opaque "solid" particles and mesh debris (depth-write, can go in G-buffer, cast shadows), (b) premultiplied-alpha blend (fire, smoke, sparks, magic — additive is just premultiplied with α = 0, so additive and alpha particles can share one blend state and one draw), (c) distortion (writes to a half-res offset buffer, like DOOM), (d) half-res "volume" smoke, (e) ribbons/trails (separate vertex topology). Simulate writes the culled index into the bucket's list (one counter per bucket); finish writes one indirect draw per bucket.
- **No bindless → one texture array per bucket.** Flipbooks are generated by code at fixed sizes, so a `Texture2DArray` of e.g. 512×512 BC7/ASTC layers (each layer an 8×8 or 4×4 flipbook) holds all VFX sprites; the emitter type stores `layer` and `frames`. Curves (size/colour/alpha over life) are baked to a 256×N `Texture2D` (R8G8B8A8 or RGBA16F) or a storage buffer of 32–64 samples, sampled by `curve_id`. Colour gradients for gradient-mapping go into the same "ramp atlas" row-per-ramp, which also fits the engine's palette+LUT style.
- **Sorting policy for a stylised look:** do not sort by default. Sort emitter *instances* back-to-front on the CPU (cheap, tens–hundreds) and record draws in that order only for the half-res smoke bucket; within an instance, rely on (1) premultiplied alpha, (2) few large shapes, (3) spawn order ≈ age order. Enable GPU bitonic sort only per-type for dense lingering smoke. Evaluate WBOIT for the half-res smoke bucket as the "never sort" fallback; it needs RGBA16F accumulation, which costs bandwidth on TBDR but at half res (≈0.5 Mpx at 1080p internal) it is small.
- **Depth collision:** borrow Wicked's previous-frame-depth bounce for sparks/debris/rain splash spawn (cosmetic only). For off-screen, fall back to the rain height map (top-down ortho depth around the camera, from threejs-punk) — this one texture serves rain, snow accumulation, splashes, "under roof" wetness masking and particle floor collision.
- **Cheap stylised lighting:** most stylised VFX should be **unlit + emissive or ramp-tinted** (fire, sparks, magic, muzzle flash). Smoke/dust need to sit in the scene: per-particle (vertex-stage) lighting = hemisphere ambient(sky/ground colours from the same ramp lighting as the world) + sun `N·L` with a sphere-ish normal + sum of ≤4 nearest clustered point lights evaluated in the simulate pass, all quantised through the project ramp. DOOM's 4K lighting atlas is overkill for our look.
- **Determinism:** split hard. Anything that changes gameplay (projectile hits, explosion damage radius, physics debris that blocks cars) lives in the CPU fixed-step sim / Jolt. GPU VFX are cosmetic and need only *reproducibility for golden captures*: fixed VFX step (60 Hz, sub-stepped, using `dt`), seed = `hash(effect_instance_seed, particle_slot_spawn_counter)` with a PCG/Squirrel-style uint hash (same family as `gen_core`), never `time·1000`. Headless captures run VFX at fixed step with interpolation alpha = 0 (matches the voxel-musou open question 5). Golden comparison should be perceptual-tolerance image diffs, not bit hashes, because GPU float atomics/ordering differs per backend.
- **No timestamp queries:** GPU cost of VFX cannot be measured per pass in-engine on SDL_GPU. Substitute *counted* proxies the engine fully controls: live particles, culled particles per bucket, overdraw (debug pass), half-res vs full-res pixel counts; measure ms out-of-band with Xcode Metal capture / Instruments.

## 2. Stylised VFX art direction (Riot, Blizzard/WoW/Overwatch, RiME, flipbooks vs procedural shaders, erosion, panning noise, gradient maps) and generating flipbooks/noise procedurally

### Takeaway
Stylised-game VFX direction converges on a small, codifiable rule set: primary/secondary hierarchy, mid-range values with brief value spikes, saturation ceiling above the environment, a single dominant hue, few hand-painted-looking shapes, non-linear timing with peak in the first quarter of life, and short lifetimes. Technically the stylised toolset is: a few greyscale shape/noise masks + alpha erosion (threshold dissolve) + UV panning/distortion + gradient-map (ramp) colouring + stepped/low-framerate time. All of that is shader math plus code-generated textures, so it fits D8/D14 well; offline ray-marched or simulated flipbooks are an optional extra, not the core.

### Cited Findings
- Riot's League of Legends VFX style guide (2017, by art director Jin Ho Yang) sets four goals — gameplay clarity, minimal clutter, supporting champion theme, surprise and delight — across gameplay, value, colour, shape and timing; primary readability traits are clear silhouette, strong shape, high opacity; importance is controlled by size, shape, timing, value, saturation and opacity — [Riot Nexus post (now redirects)](https://nexus.leagueoflegends.com/en-us/2017/10/dev-leagues-vfx-style-guide/) via search snippet; [VFX Apprentice summary](https://www.vfxapprentice.com/blog/10-league-of-legends-vfx-design-tips)
- Concrete rules (secondary summary of the Riot guide, VFX Apprentice, dated 2026-10-22): every effect has a primary element (high value, clear silhouette, high opacity, sharp focal point) and secondary elements (lower value, reduced opacity, blurred simple shapes) that "never fight the primary element"; avoid "0% pure black or 100% pure white", keep the body mid-value and reserve top values for the instant primary flash; environment saturation is the "readable floor", VFX get "a wider, higher saturation ceiling"; one dominant hue with a desaturated complementary accent; colour conventions (heal green, frost blue, gunpowder orange-red); avoid photographic textures and noisy procedural detail, mix soft and hard hand-painted shapes, "don't stack or layer too many alpha shapes"; brightest/sharpest leading edge on projectiles; non-linear timing: anticipation → impact "fully activating within the first quarter of the effect's lifespan" → smooth dissipation; keep effects short because "lingering particles cause severe overdraw costs" — [VFX Apprentice](https://www.vfxapprentice.com/blog/10-league-of-legends-vfx-design-tips)
- Riot missile anatomy: each ability gets its own design language recognisable at a glance (e.g. knock-ups use strong vertical elements) — [realtimevfx.com, Anatomy of a LoL missile pt. 2](https://realtimevfx.com/t/anatomy-of-a-league-of-legends-missile-part-2-what-are-we-communicating-with-our-vfx/13062)
- World of Warcraft: GDC 2023 Visual Effects Summit "World of Warcraft VFX Pillars" (Sarah Carmody, Blizzard) is about balancing quality, sustainability and healthy team culture, and shows internal style guides and VFX info hubs; the abstract does not list the pillars' content — [GDC Vault 1029418](https://gdcvault.com/play/1029418/Visual-Effects-Summit-World-of)
- Overwatch: VFX artist Rachel Day describes the style as "very stylized, hand-painted, basic kind of effects system" and VFX as "the visual telling of gameplay" — [VFX Voice](https://vfxvoice.com/rachel-day-the-game-changing-gamemaker-behind-overwatch/)
- GDC 2017 Visual Effects Bootcamp included Blizzard's Hadidjah Chamberlin and Riot's Jason Keyser on artistic fundamentals for VFX (content not verified) — [Game Developer](https://gamedeveloper.com/art/video-applying-artistic-principles-to-vfx-design-for-games)
- Simon Trümpler ("Simon schreibt") — Unreal Fest Europe 2018 "Stylized VFX in RiME" covers stylised fire, smoke and water; per summaries, simple textures with UV distortion produce stylised fire, and geometry with manipulated normals suits stylised effects (talk page 403, summary only) — [Unreal Engine events](https://www.unrealengine.com/events/unreal-fest-europe-2018/stylized-vfx-in-rime), [UE forum post](https://forums.unrealengine.com/t/talks-and-demos-stylized-vfx-in-rime-by-simon-trumpler-unreal-fest-europe-2018-unreal-engine/610939)
- Battlefront II layered explosion (engineered.at article, search summary only): smoke and emissive fire rendered as separate registered flipbook layers, LUT-based colour grading keeps fire/smoke colouring consistent while evolving over playback — [engineered.at](https://engineered.at/articles/battlefront-ii-layered-explosion)
- Alpha erosion: hard `a_out = step(threshold, a)` (aliases) or feathered `smoothstep`; the threshold sweep range must be widened to `[0 − feather, 1 + feather]` so the shape fully erodes; erosion maps are data and must be **linear (sRGB off)**; dithered erosion (Bayer threshold) gives pseudo-transparency on alpha-clipped opaque meshes **with no overdraw** — [vfxdoc: alpha erosion](https://vfxdoc.readthedocs.io/en/latest/shaders/alpha-erosion/)
- Practitioners drive erosion by vertex-colour alpha / per-particle custom data over life; multiplying a gradient into the mask makes erosion directional (gradient can come from an inward distance field); stepped flat-value erosion maps give a hand-animated feel — [realtimevfx: Battlerite erosion](https://realtimevfx.com/t/battlerite-erosion-ue4/4706), [realtimevfx: smoke dissolve](https://realtimevfx.com/t/smoke-dissolve-texture/1135)
- Fully procedural stylised fire (Mirza Beig, Dec 2024): no flipbook, shader math only, **time quantised** to a low frame rate to imitate hand-drawn flipbook animation, wave-offset sampling — [80.lv](https://80.lv/articles/check-out-this-fully-procedural-stylized-fire-vfx-made-with-shaders)
- Voxel Musou: bloom and additive musou waves cover 1/3–1/2 of the screen in white-yellow or green and the scene disappears; "hot-desat" exists but no global overexposure budget — hence our rule "VFX brightness and screen-coverage budget" — [voxel-musou.md §7, §8.8](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/voxel-musou.md)
- threejs-punk bloom: threshold 0 on a separate **emissive MRT**, so only what the material declares emissive blooms (neon, billboards, reflections), and bloom is attenuated by fog (`bloom·(1 − fog·0.75)`) — [threejs-punk.md §6](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

### Inferences
- **Codify Riot's rules as lints**, because they are measurable: (1) value range — fraction of VFX pixels with luminance ≥ 0.98 or ≤ 0.02 (after tonemap) below a cap except during "flash" frames; (2) peak timing — frame of max screen-luminance contribution lies within the first 25% of effect duration; (3) lifetime cap per category (e.g. hit ≤ 0.6 s, explosion fireball ≤ 1.5 s, smoke ≤ 6 s); (4) layer count — max simultaneous alpha layers per pixel; (5) hue — dominant hue within the effect's palette slot, accent saturation lower. Numbers are proposals to be tuned by the art director.
- **Stylised toolkit = 5 shader building blocks**, enough for 80% of effects: `mask(shape_id)` from SDF primitives or the shape array; `erode(mask, threshold, feather)`; `pan_distort(uv, noise_id, speed, strength)`; `gradient_map(value, ramp_id)` (row of the ramp atlas; ramps are palette-quantised); `step_time(t, fps)` for anime/hand-drawn choppiness. Fire = vertically panning noise × teardrop SDF, eroded by life, gradient-mapped black→red→orange→yellow→white with 3–5 hard steps. Smoke = round puffs eroded by a cellular/worley noise, lit by a 2-tone ramp, no additive. Magic = additive rings/glyph SDFs with ramp + sparkles.
- **Procedural flipbook generation (offline, `gen_tex` family, cached by hash like every asset):** (a) 2D: draw SDF shapes per frame (expanding ring, crown splash, star burst, lightning polyline), add domain-warped noise, quantise to palette steps — trivially cheap and fully deterministic; (b) 3D: tileable 3D noise (Perlin/Worley/curl) baked into a 32³–64³ volume or a 2D slice atlas, used for panning; (c) volumetric: ray-march a density field (sphere + FBM displaced over time, or a tiny 2D/3D smoke solver run offline) from a fixed view into an 8×8 flipbook, outputting density, a "light" channel from 1–2 directions and an emission/temperature channel; the runtime then gradient-maps temperature and lights density with the ramp. Option (c) gives the Battlefront-style registered smoke/fire layers without any DCC tool. Unity's "six-way lighting" smoke (bake lighting from 6 axes into 2 RGBA textures) is a known industry variant of (c) — not verified in this session.
- **Flipbooks vs procedural:** prefer procedural shaders for anything that must loop indefinitely (torches, campfires, neon flicker, magic auras) and flipbooks for one-shot complex shapes (explosion fireball, smoke puff, splash crown) where a baked volumetric look sells the effect. Both are "from code" under D8.
- **AI image model (D14) for VFX textures:** possible for painted shape sheets (WoW-style hand-painted wisps), but they must pass the same pipeline: convert to greyscale masks, enforce linear data, tileability, palette ramps applied at runtime. Recommend code-generated masks by default; AI only for a small "hand-painted brush shapes" sheet with provenance.
- **Emissive budget is the brightness budget:** adopt threejs-punk's emissive MRT + threshold-0 bloom so VFX only bloom when they declare emission; cap emission intensity per effect category in data; add the voxel-musou-motivated screen-coverage lint.

## 3. Effect authoring as data/code, parameter schemas, hot reload, studio preview, and how an AI agent writes and judges effects

### Takeaway
Industry systems (Niagara, Destiny) model an effect as System → Emitters → ordered modules over spawn/update stages, with per-parameter expressions and scalability overrides in a reusable "effect type". For an AI-authored engine, the right cut is: a fixed library of engine-implemented modules (C for CPU parts, HLSL for GPU parts) configured by a declarative effect file with typed, range-checked parameters and curves; hot-reloaded into the running studio; judged by headless contact sheets plus numeric lints (overdraw, brightness, coverage, timing, count, duration).

### Cited Findings
- Niagara: modules are processed top-to-bottom per stage, written in HLSL or graphs (CustomHLSL node allowed); parameters are Primitive/Enum/Struct/Data Interface; events pass data between particles, emitters and systems — [Niagara overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-niagara-effects-for-unreal-engine)
- Niagara Effect Types: one asset per category, assigned to every system, holding quality/platform overrides (cull, scale counts, disable renderers) — [Niagara scalability](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-and-best-practices-for-niagara)
- Destiny: node graph + expressions compiled to HLSL and to a CPU/GPU bytecode interpreter, targeting "sub-second iteration" — [80.lv](https://80.lv/articles/siggraph-the-destiny-particle-architecture/)
- Voxel Musou: "simulation emits, rendering listens and must not change sim state"; all VFX, sound and camera shake hang on events (`hits`, `ko`, `enemy:land`) — [voxel-musou.md §2](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/voxel-musou.md)
- threejs-punk: a central `performanceProfile` table (`*ResolutionScale`, `*FrameSkip`, `*Count`) is "exactly the quality profile struct we want"; render layers keep rain/smoke out of AO and mirror passes (maps to a `pass_mask`); presets are ~16-float structs switched without recompiling; caveat: modules that read the profile only at creation ignore later changes — [threejs-punk.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)
- Project decisions: assets are program + parameters + seed cached by hash (D8); headless mode with deterministic time step and "run N frames and dump state" (D17); studio with A/B review and an MCP server through which agents run generators, take screenshots, run lints and hot-reload (D18) — [DECISIONS.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/DECISIONS.md)

### Inferences
- **Effect file = data, modules = code.** Proposed shape (format follows whatever text data format the engine picks for recipes; JSON5/TOML-like shown):

```
effect "explosion_car_small" {
  type = "explosion"            # Effect Type: lifetime caps, budgets, LOD distances, max instances
  seed_policy = "per_instance"
  params { scale: float [0.5..3] = 1.0; fuel: float [0..1] = 0.5 }   # schema, exposed to gameplay
  layers = [
    { name="flash",   renderer="sprite", bucket="premul", count=1,  life=0.08, shape="sdf:starburst", ramp="fire_hot", emissive=4.0 },
    { name="fireball",renderer="sprite", bucket="premul", count=6,  life=[0.5,0.9], flipbook="gen:fireball_v1", ramp="fire",
      size_curve="ease_out(0.6->2.4)*scale", erode_curve="lin(0->1)@[0.3..1]" },
    { name="smoke",   renderer="sprite", bucket="halfres", count=10, life=[2.5,4], flipbook="gen:smoke_puff_v1", lit="ramp_hemi",
      spawn_delay=0.15, velocity="cone(up,35deg)*[2,4]", drag=1.5 },
    { name="sparks",  renderer="streak", bucket="premul", count=40*scale, life=[0.3,0.8], gravity=1, collide="depth", ramp="spark" },
    { name="debris",  renderer="mesh", bucket="solid", count=8, mesh="gen:debris_clump", collide="depth|height", settle=true },
    { name="shock",   renderer="distortion", count=1, shape="sdf:ring", life=0.25 },
    { name="light",   renderer="light", life=0.3, color_ramp="fire", radius=8*scale, priority=high },
    { name="scorch",  renderer="decal", life=60, shape="gen:scorch_v2", size=3*scale },
    { name="shake",   renderer="camera_shake", amp=0.4*scale, falloff=25 },
    { name="sound",   renderer="audio_cue", cue="explosion_small" } ] }
```
  Every key is validated against a schema generated from the module registry (type, unit, range, default), so an AI agent gets precise errors and the studio can auto-build parameter panels. Expressions are a tiny, sandboxed math language (constants, params, `rand`, curves) evaluated on CPU at spawn or compiled into the emitter-type struct — a deliberately smaller version of Destiny's expressions; no free-form HLSL in effect files initially.
- **Hot reload:** effect files are assets in the resource DB; on change, rebuild the emitter-type table entries and the referenced generated textures (hash-cached), keep live instances alive by re-binding type IDs. Target < 1 s from save to visible (Destiny's "sub-second iteration" goal).
- **Studio preview:** a "VFX bench" scene (neutral grey ground, dark street at night, bright noon, rain) with a looping trigger, time scrub, slow-motion, hitstop simulation, wireframe/overdraw/coverage views, and the effect's numbers live (particles, buckets, half-res pixels, light count).
- **AI authoring loop via MCP (D18):** agent edits effect file → `vfx.preview(effect, scenes, seeds)` → engine returns (1) a **contact sheet**: 8–12 frames at fixed times (e.g. 0, 0.03, 0.08, 0.15, 0.25, 0.4, 0.6, 1.0, 1.5, 2.5 s) × 3 backgrounds, plus a 1-frame "overdraw heatmap" and "luminance > threshold" mask at the peak frame; (2) a JSON metrics report; (3) lint verdicts. The agent compares against the reference sheet supplied by the art director; final approval is the owner's (roles in DECISIONS).
- **Lints (machine-checked, CI-able in headless):** max overdraw (layers/pixel, p99 and max) within category budget; mean/peak screen coverage; % pixels above luminance 0.95 after tonemap ≤ cap (the voxel-musou "brightness budget"); peak-brightness time within first 25% (Riot timing); duration ≤ category cap; live particle count and spawn burst ≤ budget; no lingering alpha below ~2% opacity (wasted overdraw); half-res bucket used for any layer whose sprites exceed N% of screen; dominant hue within declared palette slot; flicker metric (frame-to-frame luminance delta) for looping effects; textures linear for masks/erosion; every effect has an Effect Type and LOD distances.

- No published source on AI agents authoring game VFX and being judged by contact sheets; the loop above is a design proposal built on our D17/D18 decisions.
- Unity VFX Graph docs (data model, GPU events, bounds) were not fetched within budget.

## 4. Other VFX: decals, trails/ribbons, screen-space effects, weather, water splashes, destruction debris, lights from particles

### Takeaway
Decals should be projected volumes applied inside the main forward/clustered or G-buffer pass from a decal texture array (DOOM pattern), with a fixed-size ring buffer per category (bullet holes, scorches, blood, skid marks) and fading; skid marks and trails are ribbons built from a ring of points. Heat haze/shockwaves are a low-res offset buffer consumed in the final post pass. Weather is a camera-centred toroidal volume of GPU particles colliding against a top-down height/occlusion map, which also drives wetness and "dry under roofs". Debris follows the voxel-musou settle-and-persist pool. Lights from particles must be a small, prioritised, CPU-side budget.

### Cited Findings
- DOOM (2016): decals are applied while opaque meshes render in the clustered forward pass, stored in a texture atlas; each cluster references up to 256 decals (and 256 lights, 256 cubemaps); frustum split into 3,072 clusters (16×8×24, log depth slices); decals also modulate glass refraction blur — [Courrèges DOOM study](https://www.adriancourreges.com/blog/2016/09/09/doom-2016-graphics-study/)
- DOOM heat distortion: hot areas rendered into a low-resolution distortion map tested against depth (R,G = offset, B = blur amount), consumed by the final post pass; bloom at 1/4 res — [Courrèges DOOM study](https://www.adriancourreges.com/blog/2016/09/09/doom-2016-graphics-study/)
- Screen-space (deferred) decals: Pope Kim, "Screen space decals in Warhammer 40,000: Space Marine", SIGGRAPH 2012 talk; motivation: mesh-patch decals Z-fight and stretch — [SIGGRAPH history archive](https://history.siggraph.org/?p=140176), [slides](https://www.slideshare.net/slideshow/screen-space-decals-in-warhammer-40000-space-marine-14699854/14699854)
- The Surge 2 used "bindless deferred decals" (title only seen; bindless is unavailable to us) — [SlideShare](https://www.slideshare.net/slideshow/bindless-deferred-decals-in-the-surge-2/148105513)
- threejs-punk collision rain: ortho camera looking down, 512² HalfFloat **nearest** height map over 100×100 m (≈0.195 m/texel), re-centred on the player each frame; 5,000 drops in a 60×60 m volume pushed 15 m ahead of the camera with toroidal wrap; drops respawn at 20–35 m when below `height + 0.05`; streaks are 0.04×1.1 m cylindrical billboards with a purely procedural profile `(1 − |2u−1|)²` and opacity 0.15×0.45; splashes are **not tied to drop impacts** — each of 5,000 instances cycles 6×/s at random XZ with Y from the height map (≈30,000 splashes/s over 3,600 m²) — [threejs-punk.md §1](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)
- Bugs/limits found there: frame-rate-dependent integration, float seed precision, ortho camera at y = 50 with far 80 misses anything above 50 m (rain through skyscraper roofs), clear value acts as floor at y≈0; proposed extensions: reuse the map as rain occlusion for wetness (dry strips under awnings/bridges), raise drops to 30–100k on M4 Pro, stretch streaks by velocity relative to camera, depth-only ortho render (`D32_FLOAT` sampled) instead of a colour target — [threejs-punk.md §1](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)
- threejs-punk splash atlas recommendation: generate a 5–8 frame atlas (expanding ring + crown of ballistic droplets) or do it analytically in the pixel shader (ring `smoothstep` around `r(t)` + 4–6 hashed droplets) with no texture; rain ripples on ground (Huw Bowles' shader) in 3×3 cell neighbourhood; car-surface rain drops (BigWings "Heartfelt" port, credit required) — [threejs-punk.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)
- Wicked Engine has a "rain blocker" emitter option bit (same occlusion idea) — [ShaderInterop_EmittedParticle.h](https://github.com/turanszkij/WickedEngine/blob/master/WickedEngine/shaders/ShaderInterop_EmittedParticle.h)
- Voxel Musou debris: instanced clumps (2×2×2 minus one cube, inner faces removed: 84 → 48 tris); gravity 22 m/s²; on impact below −1.5 m/s bounce with −0.32 and horizontal damping ×0.55, then settle and persist; rotation ∝ 0.16/size; 2,000-instance pool casting shadows; count scaled by camera distance and by load (KO 9 pieces, officer 14, during Musou only 4); slash ribbon resampled from a **pure pose function** (no history) so trails can be sampled at 120+ Hz; ground crack decals; hitstop ages VFX at half speed; per-instance hit flash `emissive += hit·pow(1 − |N·V|, 4)`; Bayer dithered dissolve of soldiers in the camera sight cone — [voxel-musou.md §4.5–4.6, §6](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/voxel-musou.md)
- Particle lights: DOOM's clustered structure caps at 256 lights per cluster — [Courrèges DOOM study](https://www.adriancourreges.com/blog/2016/09/09/doom-2016-graphics-study/); threejs-punk has **no point/spot lights at all**; neon "light" is only emission + bloom + ground reflection — [threejs-punk.md §7](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

### Inferences
- **Decals (`decal` module):** box-projected decals evaluated in the main pass (clustered/tiled list like DOOM) if the renderer is forward+, or a deferred decal pass that modifies G-buffer albedo/normal/roughness if deferred G-buffer (M2/M6 tables say deferred). Without bindless, all decal textures go into one `Texture2DArray` (e.g. 256² or 512² layers, BC7/ASTC), generated by code: bullet holes (SDF crater + cracks), scorch (noise + radial gradient), blood/oil (metaball splats), dirt, tyre marks, graffiti/posters could also be decals. Fixed ring buffers per category (e.g. 512 bullet holes, 64 scorches, 256 blood) with oldest-first eviction and fade; distance cull. Ground cracks from voxel-musou fit here.
- **Skid marks:** not individual decals — a per-wheel ribbon mesh in a world-space ring buffer (e.g. 4 wheels × 512 segments) laid on the road surface with a small depth offset, width and alpha from slip, alpha fading over minutes; tyre smoke is a half-res smoke emitter on the same slip signal. Same ribbon code serves weapon trails (sampled from pose functions per voxel-musou), magic trails, car light trails, tracer rounds, dragon breath core.
- **Screen-space distortion:** one half-res RG16F offset target (+ optional blur in B) written by `distortion` bucket particles (heat haze over fire, shockwave rings, magic portals, exhaust), consumed in the final composite like DOOM. Mask by depth so foreground objects don't distort.
- **Weather (`weather` module):** global weather state (rain, snow, fog density, wind vector, wetness, lightning timer) driven by game/time-of-day; occlusion height map rendered depth-only top-down around the camera every N frames (or from the generator's static height data per cell + dynamic objects); GPU rain 30–100k drops with `dt` integration, velocity-stretched streaks, analytic splashes spawned on the height map, ripples + wetness (roughness/darkening) masked by occlusion; snow = slower flakes with curl-noise drift and optional accumulation mask; fog volumes = per-cell boxes/ellipsoids evaluated analytically in the fog pass (height fog + local volumes) rather than froxels at first; lightning = procedural branched polyline ribbon (midpoint displacement) + 2–3 frame sky flash + a short directional light + thunder audio delay by distance. On a planet (D15) "down" for rain/snow comes from the world-shape port's gravity at the camera, and the occlusion map is rendered along local up.
- **Water splashes / waterfalls:** splash = analytic ring + crown flipbook + droplet streaks; waterfalls = scrolling-UV mesh sheets (stylised, two panning noise layers, gradient-map foam) + mist half-res particles at the base; no fluid sim needed at our quality bar.
- **Destruction debris:** borrow voxel-musou's pool (bounce −0.32, damping, settle-and-persist, rotation ∝ 1/size, distance-scaled count) as GPU "solid" bucket particles colliding via depth/height map; hand gameplay-relevant big pieces to Jolt (as the voxel-musou note already proposes).
- **Lights from particles:** VFX layers may request a light; the CPU `vfx` module collects requests with priority (muzzle flash, explosion, magic) and keeps the top N per frame (proposal: ≤ 32 dynamic VFX lights in the cluster structure, ≤ 4 shadowless per effect, lifetime ≤ 0.3 s for flashes), rest fall back to emissive + bloom only (threejs-punk shows emissive+bloom alone already reads as "light" in a neon city). Muzzle flash = 1–2 frame sprite pair + light + smoke wisp; gunfire in a dense city must be capped by the budget, not per-weapon.

### Gaps
- No source fetched for volumetric fog (e.g. Wronski AC4 froxel fog), Unity VFX Graph decals, or skid-mark implementations in shipped racing/GTA games; skid-mark and fog proposals are inference.
- Pope Kim slides were not read in full (title/abstract only).

## 5. Performance on M4 Pro: realistic particle counts and overdraw at 1080p internal

### Takeaway
On the M4 Pro (≈ RTX 4050 Laptop class, 273 GB/s shared bandwidth) simulation of a few hundred thousand GPU particles is cheap; the real cost is fill/overdraw of large blended sprites. Our earlier budget gives the whole "sky + particles + transparents + water" row 0.6–1.2 ms at 1080p, so VFX must be budgeted by overdraw (layers × screen area), not by particle count, with big smoke rendered at half resolution.

### Cited Findings
- M4 Pro 16-core GPU ≈ RTX 4050 Laptop on modern raster (Steel Nomad 1620 vs 1613); 273 GB/s LPDDR5x shared with CPU; FP32 throughput only an unsourced estimate ~6.3–6.5 TFLOPS — [narocnost_m4_pro.md](/Users/tomasgrasl/projects/game/engine/research_notes/Schopnosti%20AI%20v%20procedur%C3%A1ln%C3%AD%203D%20grafice/narocnost_m4_pro.md) (citing Notebookcheck)
- Frame budget table: at 1080p internal (2.07 Mpx) total GPU ≈ 7–14 ms, of which "sky, particles, transparents, water" = 0.6–1.2 ms; recommended internal 1512×982 or 1080p with custom upscale — [narocnost_m4_pro.md](/Users/tomasgrasl/projects/game/engine/research_notes/Schopnosti%20AI%20v%20procedur%C3%A1ln%C3%AD%203D%20grafice/narocnost_m4_pro.md)
- Off-screen particle rendering cut particle pixels from 46.9 M to 2.9 M (4×4) or 11.7 M (2×2) and roughly doubled fps on 2007 hardware; mixed-res adds image-processing cost that can make it slower for small particles — [GPU Gems 3 ch. 23](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-23-high-speed-screen-particles)
- "Lingering particles cause severe overdraw costs" (Riot guide summary) — [VFX Apprentice](https://www.vfxapprentice.com/blog/10-league-of-legends-vfx-design-tips)
- threejs-punk runs 5,000 rain drops + 5,000 splashes via two trivial compute dispatches; half-res AO/bloom/flare/mirror is its only big saving; no ms figures are documented — [threejs-punk.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

### Inferences
- **Back-of-envelope (unverified, to be measured in M5/M6):** simulate cost ≈ read+write ~64–128 B/particle/frame; 500k particles ≈ 64 MB/frame ≈ 3.8 GB/s at 60 fps — ~1.4% of 273 GB/s, i.e. well under 0.3 ms. Blend fill: 1080p = 2.07 Mpx; an average overdraw of 2 full-res layers of cheap premultiplied sprites = 4 M blended fragments; on a TBDR GPU blending happens in tile memory, so this is ALU/fill bound rather than bandwidth bound. A starting budget: **full-res VFX ≤ ~4–6 M fragments/frame (≈ 2–3 screen-equivalents)**, **half-res smoke ≤ ~2 M fragments (≈ 4 screen-equivalents at ¼ pixels)**, live GPU particles ≤ 256k (pool 512k–1M), rain 30–100k, ≤ 32 VFX lights. These are proposals to calibrate with Xcode GPU capture, not measurements.
- Because SDL_GPU lacks timestamp queries, the in-engine budget must be expressed in counted units (fragments via an overdraw debug pass in headless captures, particles, buckets), with ms validated out-of-band on the Mac. The overdraw debug pass: re-render VFX buckets with additive `1/255` into an R8/R16 target and histogram it — cheap and deterministic, perfect for CI lints.
- Discard/alpha-test sprites can defeat TBDR hidden-surface removal (general TBDR knowledge, Apple page body not retrievable); prefer blended sprites for transparent VFX and alpha-to-coverage or dithered erosion (no overdraw) for solid-looking dissolves.

### Gaps
- No measured particle/overdraw numbers for M4 Pro or any Apple GPU were found; Apple's TBDR guidance page did not load its body.
- No data on GPU sort or atomic-append throughput on Apple GPUs via SDL_GPU/Metal.

## 6. Proposal: module layout, data format, milestone placement, lints, and what to borrow from the reference repos

### Takeaway
Add three runtime modules (`vfx`, `decal`, `weather`) plus a generator family (`gen_vfx` under the `gen_tex` umbrella) and a post hook for distortion; author effects as schema-validated data with engine modules, preview/judge them through studio + MCP contact sheets and lints; build the GPU pipeline once (global pool, buckets, single indirect draw per bucket) and grow content per milestone: transparent pass and bloom in M2, generators in M3, the VFX runtime with decals/skid marks/explosions in M5, weather/neon/half-res in M6, character hit VFX in M7, planet/magic/snow in M9.

### Cited Findings
- Existing milestone plan: M2 RHI + stylised lighting (render graph, headless PNG), M3 assets as programs (`gen_tex`, cooker, hot reload, `genlint`, golden tests, texture arrays), M4 generated world, M5 game and vehicles (fixed step, Jolt, generated cars, replay), M6 city content + open-world renderer (GPU culling into fixed slots, dither LOD), M7 characters and animation (active ragdoll), M8 scaling, M9 Planet, M10 voxel volumes (optional) — [Procedurální grafika pro engine.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/Procedur%C3%A1ln%C3%AD%20grafika%20pro%20engine.md), [STATUS.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/STATUS.md)
- Reference-repo items already prioritised in our notes: local hitstop with log scaling and VFX at ½ speed (P1), per-instance hit flash + rim (P1), sight-cone dither dissolve (P1), pose-sampled weapon trail (P2), debris pool (P2) — [voxel-musou.md §6](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/voxel-musou.md); collision rain + height map, rain occlusion for wetness, emissive-MRT bloom attenuated by fog, analytic splashes, car-surface/screen rain-on-glass, `pass_mask` render layers, quality-profile struct — [threejs-punk.md](/Users/tomasgrasl/projects/game/engine/wallhammerzero/docs/research/notes/Reference%20repa/threejs-punk.md)

### Inferences

**Module layout (CMake targets, Gregory layers per D7)**
- `vfx` (runtime, render layer): effect asset type + loader; Effect Types (budgets, LOD distances, max instances, cull rules); CPU side: instance pool with handles, emitter state machines (spawn rate/bursts, delays), event subscription from game sim (`hit`, `explode`, `skid`, `footstep`…; render only listens, per voxel-musou rule), spawn-request list, VFX light requests, camera-shake requests, audio cues out; GPU side: global particle pool, dead list, alive ping-pong, counters, emitter-type and instance storage buffers, curve/ramp atlas, flipbook `Texture2DArray`, passes `emit → kickoff → simulate(+cull, +bucket append, +depth/height collision) → [sort] → finish → draw per bucket`; renderers: sprite, streak (velocity-stretched), ribbon (trails, skid marks), mesh (debris, instanced), distortion, light, decal-spawn. Quality profile struct (counts, half-res toggle, collision on/off) read **every frame** (avoid threejs-punk's create-time read bug).
- `decal`: decal texture array, per-category ring buffers, projection volumes into the cluster/tile lists or deferred decal pass, skid-mark ribbon store (could live in `vfx` ribbons with a "persistent" flag).
- `weather`: weather state + transitions, occlusion height map pass (depth-only ortho, planet-aware "up"), rain/snow GPU emitters (as special `vfx` emitter types sharing the pool or their own small pool), wetness/occlusion outputs consumed by materials, fog volume list for the fog pass, lightning events.
- `post` additions: emissive MRT → bloom (threshold 0, fog-attenuated, half-res mip chain), distortion composite, hit flash / screen flash with a global "flash budget".
- `gen_vfx` (offline, under `gen_*`, Merkle/hash-cached, deterministic via `gen_core`): SDF shape sheets, tileable 2D/3D noise, flipbook generator (2D SDF anims, ray-marched volumetric puffs/fireballs with density/light/temperature channels), ramp/gradient generator quantised to the project palette, decal textures, debris clump meshes. Outputs go through the D14 pipeline (linear masks, BC/ASTC, provenance).
- Game-side (project DLL, not engine): which events spawn which effects, gameplay-relevant projectiles/debris.

**Data format**
- Text effect files (same syntax family as other recipes), schema generated from the module registry; units in metres/seconds (D16 scale table applies: effect sizes can reference scale-table entries like `car.length`); curves as small keyframe lists or named easing; colour only via ramp IDs from the project palette (no raw RGB except in ramps); every effect declares `type` (Effect Type) and LOD. Version field + migration like other assets. Hot reload through the resource DB.

**Milestone placement**
- **M2:** transparent pass with premultiplied blending and soft-particle depth fade; emissive MRT + bloom; headless PNG capture already exists → add overdraw debug view. (No particle system yet; a CPU-filled instanced sprite buffer suffices for the stylised-lighting reference scene: torch fire, neon.)
- **M3:** `gen_vfx` generators (shapes, noise, ramps, first flipbooks), VFX contact-sheet tool in `gencli`, lints wired into `genlint`.
- **M5:** `vfx` runtime (global GPU pool, buckets, indirect draws, depth collision, events from fixed-step sim), first effect set for vehicles: tyre smoke, skid marks, sparks on scrape, car crash debris, small/large explosion, fire on wrecked car, exhaust heat haze, muzzle flash + VFX lights; `decal` (bullet holes, scorch, oil); studio VFX bench + MCP `vfx.preview`.
- **M6:** `weather` (rain + occlusion + wetness + splashes + ripples, fog volumes, lightning), half-res smoke bucket, neon flicker/sign effects, ambient city VFX (steam vents, litter, birds as particles), LOD/budget system under dense-city load, GPU sort/WBOIT decision based on measurements.
- **M7:** character hit VFX (hit flash + rim, sparks, blood decals), hitstop coupling (VFX age at ½), pose-sampled weapon trails, dissolve/dither effects, footstep dust.
- **M9 Planet:** snow, sand/dust storms, waterfalls + mist, campfire/torch/forest fire, magic set (rings, runes, beams), dragon breath (ribbon core + fire flipbooks + distortion + ground scorch), planet-aware gravity/up in sim and weather.
