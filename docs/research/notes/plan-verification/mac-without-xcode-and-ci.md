# Mac without Xcode and CI: verifying assumptions

Research date: 2026-11-06. Machine: MacBook Pro M4 Pro, macOS 15.8.1, Command Line Tools 16.4 (clang 17.0.0, SDK macOS 15.5).

## Conclusion

Developing the engine on a Mac with only the Command Line Tools (CLT) is feasible. The SDK in the CLT has all the frameworks that SDL3 and the Metal backend need. The CLT also contain `lldb`, the sanitizers, `notarytool` and `stapler`. Without Xcode, three things are missing: the `metal`/`metallib` compiler, the GPU trace viewer and Instruments. Shaders on the Mac can therefore only go in as MSL text, which Metal compiles at startup. There will be no GPU frame debugging on the Mac at all. Our own debug views in the engine must replace it. SDL_GPU has no GPU time measurement and does not expose native Metal objects. Timing of individual passes can therefore only be obtained by patching SDL or by waiting for SDL 3.6. SDL_shadercross has no releases and Microsoft does not publish DXC for macOS. So the shader compiler must either be built from source or replaced with Slang (it has macOS ARM64 binaries, but the Metal output is marked experimental). GitHub changed its billing: the free quota is now 12 USD per month and a macOS minute costs 0.062 USD. A nightly macOS run alone therefore uses more than the whole free quota.

## How I verified

- Locally by reading only: listing the CLT folders, `xcrun -f`, `man`, `--help`. I installed nothing, built nothing and ran no third-party code.
- I read sources and documentation directly from GitHub and from the vendors' websites. I took release status from the public GitHub API.
- "Locally" in the table means: found on this machine, not from the web.
- I tried no build. Where the table says CONFIRMED for a build, it means the documentation and the SDK contents agree, not that a build was done.

## What remained unverified

- An actual build of SDL3, SDL_shadercross, DXC and Tracy with only the CLT. I built nothing.
- DXC build time on an M4 Pro.
- How long MSL compilation takes at startup and whether the system caches it between runs.
- Which Metal HUD features work on macOS 15 (per-encoder time, panel, reports).
- Capturing a `.gputrace` without Xcode.
- Running the sanitizers and `detect_leaks` in Apple clang.
- Metal with a GPU on a standard hosted macOS runner.
- WARP and lavapipe directly on GitHub runners, including running without a window.
- Vulkan SDK on macOS 15.
- The price of the Apple Developer Program and the price of the GitHub Pro plan.

## Impact on the plan

1. **Shaders on the Mac only as MSL text.** `metallib` will not be produced on the dev machine. The plan should expect compilation at startup and measure it right away (`MTL_HUD_LOG_SHADER_ENABLED=1`).
2. **The shader compiler is the first technical risk.** There is no ready macOS binary for DXC or for shadercross. The plan should include a short experiment: build shadercross with the built-in DXC into `.tools/` with only the CLT and measure the time. The fallback is Slang.
3. **Pin SDL_shadercross to a commit.** It has no releases or tags.
4. **DXIL does not have to be produced on the Mac.** It can be produced in CI on Linux or Windows, where a ready DXC exists.
5. **GPU measurement needs our own solution.** At frame level, the Metal HUD and its log are enough. It gives no time per SDL_GPU pass. Options: patch SDL in our own copy, or wait for SDL 3.6.
6. **The Mac will have no frame debugging.** Add our own debug views in the engine to the plan (viewing render targets, switching passes) and use Metal validation (`MTL_DEBUG_LAYER`, `MTL_SHADER_VALIDATION`) on every dev run.
7. **Tracy: take the ready binary into `.tools/`.** On macOS it gives only manual CPU zones, locks, memory and plots. There will be no sampling and no GPU zones through SDL_GPU.
8. **Recompute the CI budget in dollars.** Example (my calculation): a push with 5 min of Linux and 5 min of Windows costs 0.08 USD, so about 150 pushes per month out of 12 USD. A nightly macOS run of 10 min costs 18.60 USD per month. It does not fit into the Free plan.
9. **In CI, write `macos-15`, not `macos-latest`.** Otherwise the tests will run on macOS 26, which the dev machine does not have.
10. **Linux CI: install `mesa-vulkan-drivers`.** Windows CI: verify running on WARP with a short experiment before the plan relies on it.
11. **Do not use the Vulkan SDK as a source of DXC.** The current version does not officially support macOS 15 and is installed with an installer.
12. **Releasing the game works without Xcode.** All tools are available. Only the membership and the certificate are missing.

## Questions for the owner

1. **Shader compiler:** SDL_shadercross with DXC built from source (stays with SDL, one long build, no releases), or Slang (a ready binary, but the Metal output is experimental and we guard the bindings ourselves)?
2. **Shaders in the released game for Mac:** is MSL compiled at startup enough, or should a GitHub-hosted macOS runner produce `metallib`? It has Xcode, but on their machine, not on ours. **Closed: no. MSL compiled at startup is enough, Xcode is not used (D35).**
3. **macOS in CI:** a nightly hosted run costs more than the whole free quota. Options: a weekly run, paying, a self-hosted runner on the MacBook (free, runs only when the machine is on), or no macOS in CI at all and relying on local tests.
4. **GitHub Actions budget:** stay on Free (12 USD), move to Pro (18 USD), or enable payment above the limit?
5. **GPU time per pass:** is it acceptable to patch our own copy of SDL, or do we make do with the Metal HUD and wait for SDL 3.6?
6. **Apple Developer Program:** buy now, or only before the first release? Without it the game for Mac cannot be notarized.
